# R12 `--trellis 0` policy audit

The pinned SVT R8 command contains no `--trellis` option; its settings are bound by `worker/psyex-r8/runs/e05-1440/psyex-1x1/command.json`. The PSYEX source also contains no SVT CLI/configuration symbol named trellis. The only textual trellis control is the unrelated libaom API declaration `third_party/aom/inc/aom/aomcx.h:561-570` (`AV1E_SET_DISABLE_TRELLIS_QUANT`), which is not wired to the SVT app command path. Therefore `--trellis 0` is not a supported one-flag delta for this encoder and must not be presented as a delivered intervention.

The actual final EncDec behavior is controlled by `rdoq_level` and `RdoqCtrls`, not a public trellis flag. In `enc_mode_config.c:3336-3420`, `set_rdoq_controls()` maps levels 0–5. Level 1 enables RDOQ, sets `fp_q_y=1` and `fp_q_uv=1`, disables SATD skipping (`satd_factor=~0`), and sets EOB thresholds to `~0`; levels 2–5 progressively add UV skip, DCT-only, and EOB/fast thresholds. The same file’s final-PD setup around `7481-7497` sets `rdoq_level=1` for ordinary non-RTC operation, while earlier PD/light paths around `7240-7270` can select levels 4/5/0 based on pass and complexity. Runtime delivery must record the actual per-context `rdoq_level` and controls rather than infer them from preset/tune.

`full_loop.c:1700-1721` derives `perform_rdoq` from lossless status, `mds_skip_rdoq`, encode-pass state and nonzero `ctx->rdoq_level`, then may disable it through DCT/UV controls or SATD threshold. At `1726-1738`, `fp_q_y` selects the scalar-FP first quantization for 10-bit; otherwise the high-bit-depth B facade is used. Thus “RDOQ on” does not mean every TU starts with scalar FP, and “trellis off” cannot be equated to scalar B without observing these guards.

When RDOQ remains active, the final path is not just initial quantization. `full_loop.c:1768-1824` emits the first stage, applies EOB-based fast/`requant_b` decisions, then `optimize_b`; `1828-1838` may run noise normalization before `final`. Noise normalization is independently enabled by `noise_norm_strength` (`full_loop.c:1468-1540`) and can change coefficients after optimization. TU skip/lossless and pass-specific `mds_skip_rdoq` are additional confounders.

A valid future policy contrast would need a supported SVT control or private source change that explicitly sets `rdoq_level=0` while recording all resulting context controls. That would select scalar-B quantization at the first quantization branch, but it would also remove optimizer and alter later skip/EOB/noise-normalization behavior; it is a bundled real-encode policy change, not a fixed-decision diagnostic. Required guards are unchanged input/stats/build identity, exact effective per-TU `rdoq_level`, `fp_q_y`, `perform_rdoq`, stage sequence, EOB and final coefficient delivery, plus baseline q71 reconstruction equality for any local counterfactual. No outcome or one-parameter causal claim is established here.
