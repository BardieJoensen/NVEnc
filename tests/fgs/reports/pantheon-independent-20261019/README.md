# Pantheon: independent texture investigation, 2026-10-19

The 14.1-versus-10.0 Mbps objection is valid: the tested AV1 encode loses visible source texture despite spending more bits, including inside the purple shot. **The dominant measured loss in that shot occurs during lossy encoding, after the input conversion and FGS preprocessing.** A separate FGS interaction leaves retained source texture unprotected against subsequent coding loss. Neither finding proves defective NVENC hardware or a limit of AV1. No satisfactory re-encode at the original rate has been demonstrated in these controls. No production, torrent or library changes were made.

The old QVBR22 result reproduces. Within frames 96–152, original/old-encode rates are **13.725/19.186 Mbps**; within frames 120–144 they are **16.291/22.119 Mbps**. More bits really were spent in the affected shot. This rules out explaining the result solely by spending the ten-second budget elsewhere; it does not measure block-level allocation. The source has keyframes at scored indices 41/89/137/185/233, versus 144 for this NVENC sample. A source-keyframe-schedule control at 10.001 Mbps still loses texture. The two VBR points improve with rate; historical QVBR22 is consistent with that direction but uses a different rate-control mode. There is no demonstrated hard texture ceiling.

Interpretation: an already-compressed H.264 picture, including its grain and existing compression residue, becomes a new input to a different lossy optimization. A larger total bit budget does not force preservation of the previous encoder's local residuals. Ordinary generational loss and encoder allocation/search objectives are consistent with these observations; their individual contributions cannot be quantified without the master or deeper reconstruction instrumentation.

Modern SVT AC-bias=2, temporal-filter-off, and all-in-loop-filters-off controls also fail to restore the ROI at matched rate. Variance boost increases energy but produces coarser structure and poorer full-reference scores; source-selected strong-gradient retention falls to 0.697 versus 0.781 for NVENC HQ. These gradients are not a pure line-art detector. NVENC UHQ enables TF4 implicitly in this build and reduces ROI HF further; explicitly disabling its temporal filter helps but does not fix it. The complete settings, rates, PSNR/SSIM, Butteraugli, CAMBI, color shifts and timings are in [metric-table.md](metric-table.md) and [results.json](results.json). Earlier AQ-off/SVT-1.7/x264-grain controls are consistent with these results, but neither an old software version nor a same-codec second generation establishes an AV1 limit.

**FGS stages and causal evidence.** The production raw-analysis mode exposes the actual denoised/retained samples and grain table. Encoding those samples with the exported table reproduces the integrated E04 encoder's **base and grain-applied output exactly on all 240 frames**; the tables also match. All E05 raw/encoded analyzer tables match. Thus the raw stage is a validated diagnostic for this experiment, not a substitute inferred from grain-disabled decoding.

The production analyzer compares source with its preencode output; it never sees NVENC reconstruction. Source/clean safety caps can zero selected luma scaling intervals and blend original samples back into the base. Recovery holds can copy the whole source and disable synthesis. The later encoder can then discard the retained texture, with no corresponding synthesized replacement. These paths are documented against the correct source in [production-source-evidence.txt](production-source-evidence.txt).

At E04's purple ROI, the raw stage is nearly identical; the matched-rate FGS coded base has 62.9% of source HF amplitude, and synthesis brings it only to 63.2%. These are HF-amplitude ratios, not percentages of faithfully retained grain. FGS therefore cannot explain the FGS-disabled loss and does not repair that loss when enabled. The exact partition between quantization, prediction/search and hardware in-loop filtering remains unresolved; the measured localization is **downstream lossy coding**, not proof of one proprietary internal algorithm failing.

**What was missing before.** Previous extraction and GPU scoring largely reproduce. The main gaps were wrong source attribution for the binary, no actual preencode samples, sparse alignment/texture sampling, a 1.43% NVENC rate mismatch, and treating SVT 1.7 as the only independent software control. This investigation fixes those gaps. It also caught a *new diagnostic-only* pitfall: untagged raw Y4M was assumed to use a different matrix during FFmpeg output conversion. Assigning known BT.709 metadata with `setparams` before conversion restores exact raw hashes. Those invalid intermediates were excluded, and this does not invalidate the independently reproduced old QVBR22 result.

**Repair conclusion and concrete next experiment.** There is no demonstrated season-ready repair. NVENC at 20.242 Mbps is the best overall-fidelity E04 encoded arm tested here, but costs about **2.02× the original window rate**, still has only 80% of source HF amplitude with different ACF, and has not passed an E05/full-episode candidate qualification. Single-sample NVENC encodes took roughly 3 seconds for 336 frames; SVT baseline took 25 seconds and variance boost 45 seconds on restricted CPU resources. These are shared-host sample timings, not clean throughput or season-size forecasts.

The strongest next experiment is a **controlled residual-allocation test**, not another undirected preset sweep: in a scratch SVT 4.2 build, export the temporally filtered input and pre/post-loop reconstruction and log per-superblock qindex/residual allocation for E04 and the E05-1440 shirt. Repeat baseline and texture-directed allocation at actual source rate. In parallel with that causal control, an offline grain-model experiment can fit *source minus decoded base* under the existing edge/quiet-region caps and compare it with the current preencode model. That tests whether coding-aware synthesis can restore lost stochastic texture without injecting noise into intentional lines/flat regions. A global FGS-off change, encoder swap, or restoration of source samples inside the denoiser is not supported as the production repair.

Only a candidate passing these checks warrants a production-change plan: actual video rate within 1% on each primary fixture; preserved geometry/color/alignment; native crop inspection plus synchronized temporal viewing of line detail and textured effects; amplitude **and** ACF/color dependence/scene transitions consistent with source (provisional ROI screening: amplitude within 10%, ACF1 within 0.05, explicitly not a perceptual guarantee); no new banding or full-reference tail regressions; then full E04/E05 and representative season episodes with actual sizes, runtime, seek/FGS validation and the user's real player/display. Thresholds are proposed screening criteria, not an already-approved gate. Original-video restoration remains an exact-source fallback, not evidence that efficient AV1 re-encoding is impossible.
