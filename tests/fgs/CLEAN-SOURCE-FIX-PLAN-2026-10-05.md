# Proposed next change: protect clean source regions

Fixing unwanted grain is the next priority. Production demonstrably adds noise to constant picture regions in both animation and live action, and one strong case survives a full encode from the beginning. The proposed change strengthens the existing source-safety path at clean black/white and neutral-colour regions; it does not restart the parked retention project. This plan requires the user's go before any output-changing implementation.

## Bounded implementation proposal

1. Freeze the new witnesses and their source/mask/PTS receipts. Add a small causal control with identical grainy background and constant active-picture panels at source luma 16, 20, 21, 32, 231, 232, 234, plus neutral chroma; vary only panel level or the presence of actual letterbox bars. Render the existing table through the real decoder and compare against unchanged/clipped base. This separates the endpoint eligibility hypothesis from fitting, clipping and scene history.
2. Inspect the existing production `protectSource`, quiet-source and source-variance caps at the first affected frames. Make exact constant-source evidence a hard zero-synthesis constraint where the format can represent it; do not allow the ordinary small-excess tolerance to turn zero evidence into a positive grain allowance. Preserve both chroma planes and native bit-depth behavior. Guard partial blocks and true picture boundaries explicitly.
3. Distinguish verified active-picture evidence from bars without inventing a universal crop detector. Reuse production source evidence and existing cap/source-blend machinery. If a frame-wide curve cannot satisfy a clean region while retaining legitimate grain at the same lookup codes, use a conservative existing fallback and measure its size cost; do not silently relax the clean-source requirement or introduce spatial grain syntax that AV1 does not have.
4. Make a safety decrease immediate when new clean evidence arrives; any temporal smoothing or recovery must not hold an unsafe grain level across a clean shot. Check scene cuts and source-supported restarts before changing model history. The separate Knightfall temporal defect may need a later slice if the safety correction does not resolve it.

This is an initial 1–2 engineering-day diagnosis/prototype budget plus about one day for the existing qualification and bounded original-source tests, subject to GPU availability. If the format conflict makes the byte cost unacceptable, stop and present that evidence; do not grow another retention framework.

## Measurements and kill criteria

Use production, the proposed safety candidate and plain NVENC on the **same originals**, all with matched measured video payload bitrate (target within 1%; an unmatched case is unresolved). Preserve the production decode, colour, bilateral and encoder settings. Rate adjustment is only for this quality comparison, not a general encoder-knob search. Report fixed-QVBR size effects separately so that matching bitrate does not conceal a large operating-cost regression.

- **Clean safety:** source-self and clipping controls must remain zero; every retained exactly constant-source witness must have zero decoded synthesis beyond the applicable no-grain/clipping null in Y/Cb/Cr. A positive at any occupied source brightness level fails this target. Add a small independently selected clean original window per content class before inspecting candidate results. Finite tests do not establish a universal promise about all unobserved pixels.
- **Temporal safety:** eliminate the confirmed excess/jump without creating a neighboring excess, delayed clean-shot response or unsafe recovery. Compare source, decoded base, added grain and played texture together. Do not optimize table stability alone.
- **Legitimate grain:** compare source-relative amplitude and HF sigma jointly with horizontal/vertical lag 1/2, per occupied luma band and each plane, on existing grainy originals and at least one 4K HDR title. Kill a proposed improvement if it fixes clean patches by broadly stripping legitimate grain, if an established full-gate regression appears, or if its gain disappears at equal bytes.
- **Cost:** a standalone safety change must pass the unchanged full gate and avoid more than 2% fixed-QVBR video-byte growth on either 1080p development stratum or the tested HDR title; report the per-title numbers, with no invented library average. This is a proposed experiment budget, not a change to an existing release gate. If a stricter clean guarantee requires greater cost, return for a product decision rather than hiding it in an average.
- **Artifact guard rails:** use the existing source-aligned GPU FR/CAMBI checks to catch banding, blocking, colour shift, detail loss and ghosting. They are not the grain objective. Retain native frames around any new worst event; make review clips only after the candidate meets the declared target.
- **Scope:** stop the prototype if fixing it requires a new separator, a broad source estimator, an R3–R8 extension or an AV1 format change. Those would need a separately justified plan.

No implementation of this plan, deployment, image swap, push, library scan or repair is included in the current continuation.
